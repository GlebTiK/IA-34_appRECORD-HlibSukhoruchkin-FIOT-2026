## Тема, Мета, Місце розташування

Тема: «Розробка функціонального REST API. Реєстрація та авторизація користувачів. Валідація даних і обробка помилок.»

Мета: розширити веб-застосунок **Puppy Haven**, створений у попередній лабораторній роботі, без зміни його статичної клієнтської частини. У роботі потрібно повторно використати сторінки та матеріали Lab 2, а серверну частину доповнити реєстрацією, авторизацією, JWT-захистом маршрутів, валідацією даних, ролями користувачів, logout, refresh token і обробкою помилок.

## Постановка задачі

У якості основи використано проєкт Lab 2 **Puppy Haven**, у якому вже реалізовано:
- статичну клієнтську частину сайту;
- видачу списку цуценят через REST API;
- створення та перегляд заявок на візит;
- зберігання даних у MySQL за допомогою Sequelize.

У лабораторній роботі №3 структура проєкту була збережена, а наявний backend розширено модулем автентифікації та авторизації. Таким чином, Lab 3 є продовженням Lab 2, а не окремим новим проєктом.

## Що повторно використано з Lab 2

У роботі без змін або з мінімальними змінами повторно використано:
- папку `public` зі статичними HTML/CSS/JS файлами;
- конфігурацію підключення до MySQL;
- моделі `Puppy` і `VisitRequest`;
- маршрути отримання цуценят і створення заявок на візит;
- загальну структуру Express-проєкту.

Це дозволило зберегти цілісність веб-застосунку та показати послідовний розвиток проєкту від Lab 2 до Lab 3.

## Структура проєкту після доопрацювання

- `public/` — статична частина сайту з Lab 2;
- `config/database.js` — підключення до MySQL;
- `models/Puppy.js` — модель цуценяти;
- `models/VisitRequest.js` — модель заявки;
- `models/User.js` — нова модель користувача;
- `models/RefreshToken.js` — нова модель refresh token;
- `models/index.js` — зв’язки між усіма моделями;
- `routes/auth.js` — маршрути реєстрації та авторизації;
- `middleware/auth.js` — перевірка JWT;
- `middleware/role.js` — перевірка ролі;
- `middleware/loginLimiter.js` — обмеження спроб входу;
- `middleware/errorHandler.js` — централізована обробка помилок;
- `server.js` — головний файл сервера;
- `sql/schema.sql` — SQL-схема з новими таблицями.

### Успадковані з Lab 2

- `GET /api/health`
- `GET /api/puppies`

## Валідація та безпека

У роботі реалізовано:
- перевірку формату email;
- перевірку мінімальної довжини пароля;
- підтвердження пароля під час реєстрації;
- перевірку старого пароля при зміні на новий;
- хешування паролів через `bcryptjs`;
- використання JWT для захисту маршрутів;
- перевірку ролей користувачів;
- rate limit для входу;
- логування помилок у файл.

## Приклади запитів

### Реєстрація

```bash
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d "{\"full_name\":\"Hlib Sukhoruchkin\",\"email\":\"hlib@example.com\",\"password\":\"secret123\",\"password_confirm\":\"secret123\"}"
```

### Авторизація

```bash
curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"email\":\"hlib@example.com\",\"password\":\"secret123\"}"
```

### Отримання профілю

```bash
curl http://localhost:3000/api/auth/me \
  -H "Authorization: Bearer ACCESS_TOKEN"
```
